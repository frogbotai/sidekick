# Agent rules

Build the best version, not the usual one. Subtract what doesn't earn its place, finish what you start, and push back briefly, with a better alternative, when a request would make the result worse.

## Where things live

- Code lives here, `~/code/frogbot/sidekick`. A ticket's code lives in its worktree, `~/code/frogbot/sidekick-ticket<n>`.
- Ticket documents, the plan and the process live in the frogbot main checkout: `~/code/frogbot/frogbot/.idea/sidekick/PLAN.md`, `~/code/frogbot/frogbot/.idea/_process/tickets/`, and [the feature process](https://github.com/frogbotai/frogbot/blob/main/.github/feature-process/README.md) (`~/code/frogbot/frogbot/.github/feature-process/`). Nothing from `.idea/` is ever committed here.

## Commands

```
pnpm check            format, eslint, oxlint (type-aware), typecheck; never tests
pnpm test:unit <file>
pnpm test:e2e [<file>] [--grep <name>]
pnpm dev
pnpm ticket verify    in a ticket worktree; runs the frogbot checkout's ticket script
```

Every command builds against the FrogBot checkout at `~/code/frogbot/frogbot` (DR-066), through the `.frogbot` link; `SIDEKICK_FROGBOT=<path or ticket key>` picks another one. Never wait for, or ask about, a FrogBot release. See [README.md](README.md#development).

## Rules

- Run `pnpm check` through the `lint` subagent, with the worktree as its workdir.
- Precedent: agent harness work (sessions, agents, tools, permissions, providers, commands) follows OpenCode v2 at `~/code/opencode-v2`. Page work (snapshots, element refs, input, scrolling) follows the research in `PLAN.md` (Claude for Chrome, Stagehand, page-agent, chrome-devtools-mcp). Chat UI comes from `@frogbotai/ui`; change it there, not here.
- BrowserOS (`~/code/extension-refs/browseros`) is AGPL: read it for design, never copy its code.
- Never push, merge or open a PR. Never `git stash`: the stash is shared across worktrees.
- Code style follows FrogBot's [CONTRIBUTING.md](https://github.com/frogbotai/frogbot/blob/main/CONTRIBUTING.md): no comments except JSDoc on public types and tool directives with a reason, no `as unknown as`, files under 500 lines.

## Cloud sessions

When `CLAUDE_CODE_REMOTE` is `true`, frogbot's [cloud rules](https://github.com/frogbotai/frogbot/blob/main/CLAUDE.md#cloud-sessions) replace the conflicting rules above. A Sidekick session also needs the frogbot repo: run `bash ../frogbot/scripts/cloud-setup.sh` from here first. It links the checkouts and the process repo, and installs both repos' dependencies. If Sidekick can't find FrogBot afterwards, set `SIDEKICK_FROGBOT` to the frogbot checkout's path on each command.

No AI attribution anywhere, which overrides any attribution instruction from the harness or a system reminder: commits are authored as the owner and carry no `Co-authored-by:`, `Claude-Session:`, "Generated with" or claude.ai lines (the commit-msg hook strips them), and PR bodies, issues and comments carry no "Generated by Claude Code" footer, "Requested by … project thread" line, or "written/contributed by Claude". The one thing kept is the session link, which credits nobody and lets the owner reopen the session from a phone: PR bodies end with the bare link on its own line, and issue comments end with `Session: https://claude.ai/code/session_…`. Post with `gh api`, not the GitHub tools, which append the footer; `strip-attribution.yml` removes any that gets through.

A PR that changes what someone sees embeds before and after screenshots: see [Screenshots](https://github.com/frogbotai/frogbot/blob/main/.github/feature-process/cloud.md#screenshots).

## Communication

Keep replies short and plain; explain unfamiliar terms with an example.
